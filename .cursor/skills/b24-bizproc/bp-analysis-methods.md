# Методы работы с бизнес-процессами Битрикс24

Универсальная методология для агента. **Не хранить** разбор конкретных шаблонов — только способы анализа и отладки.

---

## 1. Источники данных

| Источник | Когда |
|----------|--------|
| Экспорт `.bpt` с портала | Структура шаблона, Activated, условия, SetField |
| Журнал БП на документе | Фактический путь выполнения, логи, время стартов |
| Поля CRM-документа | Почему сработало/не сработало условие |
| `bizproc.workflow.instances` (REST) | Активные экземпляры, дубли |
| Справочник UF | `заявка-на-договор/export/bp-608-fields-table.md` — код → русское имя |

**Правило:** шаблон + журнал + поля сделки. Один экспорт без журнала — неполная картина.

## 2. Экспорт `.bpt` — формат и инструменты

| Факт | Деталь |
|------|--------|
| **Не ZIP** | `zlib deflate` + PHP serialize |
| Распаковка | `zlib.inflateSync(fs.readFileSync(path)).toString('utf8')` |
| Скрипт | `Me/Me/Личное/Работа/bitrix24/заявка-на-договор/scripts/analyze-bpt-export.js` |
| Полный разбор | `parse-bpt.js` → summary в `export/` |

```bash
node Me/Me/Личное/Работа/bitrix24/заявка-на-договор/scripts/analyze-bpt-export.js "path/to/export.bpt"
```

**PowerShell:** не использовать `$var` в однострочниках через агента — переменные съедаются. Писать `.js`-скрипт в workspace.

`AUTO_EXECUTE`: `2` = при изменении, `3` = при создании и изменении.

В тексте шаблона искать: `SetFieldActivity`, `StartWorkflowActivity`, `s:9:"Activated"`, `fieldcondition`, `LogActivity`, `EditorComment`.

## 3. Чеклист разбора шаблона

1. Тип автозапуска (создание / изменение / вручную).
2. Считать **активные** `SetField` и **активные** `StartWorkflow` (по `TemplateId`).
3. Для каждого спорного блока — **`Activated` на блоке и всех родителях** (отключённый родитель = ветка мёртва на портале).
4. Условия входа в ветки: `fieldcondition`, `truecondition`, пустые ветки.
5. Кто пишет в `OPPORTUNITY`, `STAGE_ID`, служебные UF (история, «хранение»).
6. Вложенные БП: сколько раз и какой `TEMPLATE_ID`.
7. Сравнение версий экспорта: diff по количеству активных SetField и отключённым шагам.

**Не делать выводов** «ветка X выполняется», пока не проверен `Activated` по всей цепочке.

---

## 4. Автозапуск «при изменении» — модель

### Верно

- Изменения **внутри одного** экземпляра БП **не** перезапускают тот же шаблон на **каждый** шаг «Изменение документа».
- БП **не автозапускается**, если документ изменён **другим** бизнес-процессом ([справка](https://helpdesk.bitrix24.ru/open/25296800/)).
- Поля в CRM обычно обновляются **по ходу** шагов; блокируется **повторный автозапуск**, а не запись в БД.

### Неверно (не утверждать)

- «N шагов SetField в одном проходе = N новых экземпляров БП».

### Реальные причины множественных запусков

1. Несколько **внешних** сохранений (пользователь, робот CRM, REST, интеграция).
2. Явный **«Запуск бизнес-процесса»** в шаблоне или из другого БП.
3. Другие шаблоны с автозапуском «при изменении» на той же сущности.
4. Роботы CRM, меняющие поля **вне** контекста подавления автозапуска БП.

## 5. Отладка инцидента на документе

1. Журнал БП: ID экземпляров, время старта/конца, тексты `LogActivity`.
2. Сопоставить с таймлайном сделки (кто сохранил, робот, интеграция).
3. Проверить: ожидаемая ветка **не вошла** из‑за условия — что в полях?
4. «Блок не выполнился» ≠ «БП почти ничего не сделал» — соседние ветки и параллельные блоки могли отработать.
5. При сравнении версий шаблона — смотреть **текущий экспорт с портала**, не старый файл с диска.

---

## 6. Типичные антипаттерны (рекомендации по дизайну)

| Проблема | Подход |
|----------|--------|
| Лишние перезапуски снаружи | Условие «нужно ли действие» в начале; не писать без изменения |
| Много SetField подряд | Объединить поля в один «Изменение документа» |
| БП на изменение с паузами/ожиданием | Убрать паузы ([урок Б24](https://dev.1c-bitrix.ru/learning/course/?COURSE_ID=57&LESSON_ID=8445)) |
| Условие на одно UF, бизнес на другое | Сверить код поля с карточкой и справочником |
| Каскад вложенных StartWorkflow | Пересмотреть необходимость каждого дочернего шаблона |

---

## 7. Поведение агента

- Анализ `.bpt` и скрипты — **выполнять самому**, без запроса «можно ли запустить».
- **Не сохранять** в skill/playbook структуру конкретных шаблонов портала — только методы.
- Итоги разбора конкретного БП — в ответ пользователю или в `context.md` → журнал (кратко), не в постоянную базу шаблона.
- Перед массовыми правками на портале — тест на одной сделке/записи.
