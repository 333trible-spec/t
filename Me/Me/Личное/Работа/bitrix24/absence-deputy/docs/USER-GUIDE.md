# 6 кадров — инструкция для пользователя

Локальное приложение Битрикс24 на портале **ik-navigator**.  
Версия: **0.8.1** · адрес: https://app-d561d9d4f2bd.vibecode.bitrix24.tech

---

## Кому доступно

Работать с приложением может только один пользователь портала (администратор кадров / владелец приложения).  
Остальным при открытии показывается экран **«Доступа нет»**.

Откройте приложение из меню портала (как зарегистрированное локальное приложение). Если страница «залипла» на старой версии — обновите iframe: **Ctrl+F5**.

---

## Что делает приложение

Две вкладки:

| Вкладка | Назначение |
|---------|------------|
| **Отпуск** | Запись отпуска с заместителем; контроль делегирования заданий бизнес-процессов |
| **Увольнение** | Уволить сейчас или запланировать на дату; отмена плана |

---

## Вкладка «Отпуск»

### Создать отпуск

1. **Сотрудник** — «Выбрать сотрудника» (обязательно).
2. **Заместитель** — «Выбрать замещающего» (обязательно, не тот же человек).
3. **С** / **До** — период подмены.
4. В блоке **«Затронутые роли»** видно, какие константы затронет подмена.
5. Нажмите **«Запланировать отпуск»**.

**Как считаются даты**

- Подмена действует **с даты «С» включительно**.
- Если «С» = сегодня — подмена считается активной сразу после сохранения.
- Дата **«До» в период не входит**: в этот день подмена уже не действует (возврат).
- «До» должна быть **строго позже** «С».

Кнопка **«Сбросить»** очищает форму.

### Таблица «Отпуска»

| Колонка | Смысл |
|---------|--------|
| Сотрудник | Кто в отпуске |
| Период | С – До |
| Заместитель | На кого подмена |
| Статус | **Запланирован** / **Активен** / … |
| Делегирование | Результат последней проверки заданий БП |
| Константа | Есть ли сотрудник в отслеживаемых константах |

**Статусы**

| Статус | Когда |
|--------|--------|
| Запланирован | Сегодня ещё раньше даты «С» |
| Активен | Сегодня в интервале `[С; До)` |
| (не показывается) | После «До» запись из списка убирается как завершённая |

**Колонка «Делегирование»**

| Значение | Значение |
|----------|----------|
| **—** | Ещё не проверяли (крон не бегал / отпуск не активен) |
| **ок** | У отпускника нет открытых заданий БП (всё ушло заместителю или заданий не было) |
| Красный текст | Часть заданий осталась у отпускника — наведите курсор, увидите список |

> «ок» — это результат **последнего** прогона. Если после него у сотрудника появилось новое задание, статус обновится только после следующего запуска делегирования.

### Кнопки у списка отпусков

| Кнопка | Действие |
|--------|----------|
| **↻** | Обновить таблицу |
| **▶** | Сейчас запустить делегирование всех активных отпусков (как «Run now» у крона) |

Перед **▶** приложение спросит подтверждение **«Запустить сейчас?»**.

Автоматически делегирование запускается по расписанию (Екатеринбург): **08:00, 11:00, 14:00, 17:00**.  
Между прогонами новые задания у отпускника могут ещё числиться на нём — это нормально.

## Вкладка «Увольнение»

### Уволить сотрудника

1. Выберите **сотрудника** (или введите **ID** и нажмите **«Найти»**).
2. Выберите режим даты:
   - **Сейчас** — сразу после подтверждения;
   - **С даты** — укажите день: срабатывание в начало этого дня (таймзона портала).
3. При необходимости укажите **замещающего** (кому перейдут роли/константы в момент увольнения).
4. Просмотрите блок превью ролей.
5. Нажмите **«Уволить»** и подтвердите в диалоге.

Сотрудник на портале **деактивируется** (нельзя войти). Операция необратима с точки зрения «уволен»; отменить можно только **запланированное** увольнение до исполнения.

Кнопка **«Сбросить»** очищает форму.

### Таблица «Увольнения»

| Колонка | Смысл |
|---------|--------|
| Сотрудник | Кого увольняют / уволили |
| Дата | Дата плана или факт |
| Статус | Запланировано / Ожидает / Уволен / Ошибка / Отменено |
| Действия | **«Отменить»** — только для ещё не выполненного плана |

**↻** — обновить список.

Если в статусе **«Ошибка»** — смотрите комментарий/повтор после исправления данных; при необходимости создайте план заново.

## Типовые сценарии

### Отпуск на неделю с подменой заданий БП

1. Вкладка **Отпуск** → сотрудник + заместитель + даты.
2. Сохранить.
3. Когда отпуск **Активен**, открытые задания БП уходят заместителю по крону (или сразу через **▶**).
4. В колонке **Делегирование** должно стать **ок** после прогона.

### Срочное увольнение

1. Вкладка **Увольнение** → сотрудник → **Сейчас** → (опционально заместитель) → **Уволить** → подтвердить.
2. В таблице статус **Уволен**.

### Увольнение «с понедельника»

1. Режим **С даты** → выбрать понедельник.
2. До наступления даты можно нажать **Отменить** в таблице.
3. В день даты сработает ночной/утренний cron увольнений (около **02:00** и страховка **03:30** YEKT).

## Частые вопросы

**Почему «Доступа нет»?**  
Вы вошли не тем пользователем, которому разрешено приложение.

**Почему делегирование «ок», а задание ещё у отпускника?**  
Либо задание появилось **после** последней проверки, либо крон ещё не дошёл до этого часа. Нажмите **▶** или дождитесь ближайшего слота 08/11/14/17.

**Почему кнопка отпуска «Запланировать», если «С» — сегодня?**  
Формулировка общая; при «С» = сегодня запись сразу считается активной.

**Меняются ли все глобальные константы?**  
Список затронутых ролей показывается в форме. Полная автоматическая запись GlobalConst — по стратегии администратора; делегирование заданий БП работает через крон / ▶.

**Можно ли вернуть уже уволенного?**  
Через это приложение — нет. Нужна обычная реактивация пользователя в Б24 администратором.
