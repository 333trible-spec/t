# Универсальный список «6 кадров — записи»

Хранилище отпусков и увольнений на портале **ik-navigator** (REST `lists.*`).

## Список

| | |
|---|---|
| **ID** | **276** |
| Код | `SIX_STAFF_RECORDS` |
| Название | **6 кадров — записи** |
| Доступ | только user **24880** (`U24880`: полный, `*`: запрет) |
| Тип | `lists` |

## Видимые поля

| Поле | В UI списка |
|---|---|
| Тип | Отпуск / Увольнение |
| ФИО | ФИО сотрудника |
| Статус | Запланировано / Выполнено / … |
| Замещающий | ФИО замещающего |
| Комментарий | Причина ошибки (делегирование / cron) |

## Настройка (один раз)

1. **Webhook** — добавить scope **`lists`**, обновить URL в `B24_NAV_WEBHOOK` (Vercel + локальный `.env`).

2. **Создать список и поля:**
   ```bash
   cd absence-deputy
   node scripts/setup-six-staff-list.mjs
   ```
   Результат: `data/six-staff-list.json` (ID списка и PROPERTY_* полей).

3. **Деплой** — файл `data/six-staff-list.json` должен попасть на Vercel (уже в `includeFiles`).

4. Опционально env **`SIX_STAFF_LIST_IBLOCK_ID`** — если config не в репозитории.

## Поведение приложения

| Действие | УС |
|---|---|
| Уволить **с даты** | `lists.element.add`, статус «Запланировано» |
| Уволить **сейчас** | запись со статусом «Выполнено» |
| **Cron** 02:00 и 03:30 YEKT | внешний cron-job.org → POST `/api/dismissal-cron` (см. [[CRON-JOB-ORG.md]]) |
| **Отмена** плана | статус «Отменено» |
| **Отпуск** (форма) | POST `/api/vacation` → элемент «Отпуск» |
| Таблицы UI | чтение из УС (если настроен), иначе fallback HR CRM / Redis |

Приоритет хранилища: **УС** → Redis → локальный файл.

## Где смотреть в Б24

**CRM → Ещё → Списки** (или **Компания → Списки**) → **6 кадров — записи**.
