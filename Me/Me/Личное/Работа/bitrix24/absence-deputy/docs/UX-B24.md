# UX/UI — «6 кадров» (нативный Битрикс24)

Спецификация интерфейса локального приложения на портале **ik-navigator.bitrix24.ru**.  
Стиль: **нативный Б24** (официальный [B24 UI Kit](https://apidocs.bitrix24.com/api-reference/widgets/ui-kit/index.html)).  
**Не использовать:** Micra/Futura, градиенты и палитру «Навигатор. Девелопмент».

Техническая папка: `absence-deputy`. Код приложения и зависимости здесь не описываются — только UX.

Источники компонентов и токенов (сверять перед вёрсткой):

- [Quick Start](https://apidocs.bitrix24.com/api-reference/widgets/ui-kit/quick-start.html)
- [B24 UI components](https://bitrix24.github.io/b24ui/docs/components/)
- [bitrix24/b24ui](https://github.com/bitrix24/b24ui)

---

## 1. Цель и роли

| | |
|---|---|
| **Задача** | Управлять подменой user-констант на отпуск и готовить увольнение с прозрачным влиянием на роли |
| **Кто** | Все сотрудники портала |
| **Где** | Локальное приложение Б24 (iframe), две микространицы-вкладки |
| **Не делаем** | Уведомления Б24, запись в календарь отсутствий, брендбук Навигатора |

Права UI не ограничиваем: любой сотрудник видит обе вкладки и может создавать записи. Ограничения записи констант — зона Витька (если появятся — отразить disabled + tooltip).

## 2. Семантика дат (обязательно для UI и cron)

### 2.1. Отпуск: «С» и «До»

**Правило (exclusive end):**

| Момент | Действие |
|--------|----------|
| Начало календарного дня **«С»** (таймзона портала) | Автоподмена: во всех user-константах, где указан сотрудник, ставится заместитель |
| Запись создана в сам день **«С»** | Подмена выполняется сразу после сохранения, без ожидания следующего дня |
| Начало календарного дня **«До»** | Автовозврат: во всех затронутых константах снова сотрудник |
| День **«До»** | Уже **без** подмены: в константах оригинал |

**Интервал подмены:** `[С ; До)` — день «С» включительно, день «До» **не** входит в период подмены.

Дата **«С»** может быть сегодня или в будущем. Дата **«До»** должна быть строго позже даты «С»; нулевой интервал не сохраняем.

**Ручной возврат:** доступен для статусов «Запланирован» и «Активен»; после возврата статус «Возвращён», автовозврат в день «До» не нужен (noop).

### 2.2. Текст подсказки у полей дат (Отпуск)

Показывать под полями «С» / «До» (hint компонента поля):

> Подмена действует с даты «С» включительно. Если «С» — сегодня, она включится сразу после сохранения. В дату «До» выполняется автовозврат: в этот день в константах уже снова сотрудник, а не заместитель.

Формат дат — локальный формат портала (как в B24 DatePicker).

### 2.3. Увольнение: дата

| Режим | Когда срабатывает |
|-------|-------------------|
| Уволить сейчас | Сразу после подтверждения |
| Уволить с даты | В **начало** выбранного календарного дня (таймзона портала) |

Автовозврата констант нет. Если указана замена — перевод констант на заместителя в тот же момент, что и увольнение.

## 4. Компоненты B24 UI Kit

Имена сверять с актуальной документацией Kit перед кодом. Ниже — целевая семантика.

| Задача UI | Компонент Kit (ориентир) | Примечание |
|-----------|--------------------------|------------|
| Оболочка страницы | layout / page контейнер Kit | Короткий заголовок, без декора |
| Вкладки | Tabs / Tab | «Отпуск» · «Увольнение» |
| Заголовок секции | Typography / Heading | H1 приложения один раз в shell |
| Поля формы | FormField + Input / DatePicker | Обязательность и ошибка у поля |
| Сотрудник / заместитель | штатный **селектор сотрудников Б24** (entity-selector / UserSelector через BX24) | Аватар, ФИО, подразделение; не text input |
| Режим увольнения | RadioGroup | «Сейчас» / «С даты» |
| Основное действие | Button (primary) | «Запланировать отпуск» / «Уволить…» |
| Вторичное | Button (outline / plain) | «Отмена», «Закрыть» |
| Опасное | Button (danger) | Ручной возврат, подтверждение увольнения |
| Таблица | Table | Строки + меню действий |
| Статус | Badge | Цвета токенов Kit, не кастом hex |
| Предупреждения | Alert / Banner | Тест-режим, пустые константы, дата начала сегодня |
| Пусто | Empty | Иллюстрация/иконка Kit + CTA |
| Загрузка | Skeleton / Spinner | Таблица и превью констант |
| Конфликт / подтверждение | Modal / Dialog | Фокус в модалке, Esc = отмена |
| Подсказка дат | Hint / Description у FormField | Текст §2.2 |
| Длинный список ролей | Collapsible / список + «ещё N» | Не ломать высоту iframe |
| Меню строки | DropdownMenu | «Вернуть», «Подробнее», «Отменить план» |

Токены: цвета, радиусы, отступы, типографика — **только** design tokens B24 UI Kit. Светлая/тёмная тема — через токены Kit, без ручных hex.

## 5. Вкладка «Отпуск»

### 5.1. Структура (сверху вниз)

1. Alert тестового режима (если вкл.)
2. Блок формы «Новый отпуск»
3. Разделитель / заголовок «Отпуска»
4. Фильтр статуса (опционально compact: Все / Активные / Запланированные / Завершённые)
5. Таблица

### 5.2. Поля формы

| Поле | Тип | Обязательно | Правила |
|------|-----|-------------|---------|
| Сотрудник | селектор Б24 (один) | да | Нельзя выбрать себя и заместителя одним человеком? → **запрет:** сотрудник ≠ заместитель |
| Заместитель | селектор Б24 (один) | да | Любой сотрудник портала |
| С | DatePicker | да | `с ≥ сегодня`; если `с = сегодня`, применить сразу |
| До | DatePicker | да | `до > с` |

После выбора сотрудника — блок **«Затронутые роли»** (loading → список названий констант, где он указан; в тесте — только «Проджект Б24» или empty «В тестовом режиме константы не затронуты / не найдены»).

### 5.3. Действия формы

| Действие | Когда | Результат |
|----------|-------|-----------|
| Запланировать отпуск | Валидная форма | Создание записи; при конфликте → A3 |
| Сбросить | Есть черновик | Очистка полей |

Primary справа от заголовка блока или под формой (одна колонка на узком iframe).

### 5.4. Таблица отпускников

Колонки:

| Колонка | Содержание |
|---------|------------|
| Сотрудник | Аватар + ФИО |
| Период | `ДД.ММ.ГГГГ – ДД.ММ.ГГГГ` + мелкий hint «подмена до даты „До“, не включая её» |
| Заместитель | Аватар + ФИО |
| Роли | Число + первые 1–2 названия; клик → A5 |
| Статус | Badge |
| Действия | Меню |

**Статусы:**

| Статус | Badge | Смысл |
|--------|-------|-------|
| Запланирован | secondary / info | Сегодня &lt; «С» |
| Активен | success / primary | «С» ≤ сегодня &lt; «До» |
| Возвращён | neutral | Ручной или автовозврат выполнен |
| Ошибка | danger | Сбой записи констант (детали в строке/toast) |
| Отменён | neutral muted | План снят до «с» |

**Действия строки:**

| Статус | Действия |
|--------|----------|
| Запланирован | Отменить план · Подробнее |
| Активен | Вернуть сейчас · Подробнее |
| Возвращён / Отменён / Ошибка | Подробнее · (повтор при Ошибка — если Витьёк даст API) |

### 5.5. Состояния вкладки

| Состояние | UI |
|-----------|-----|
| Loading | Skeleton таблицы + disabled форма или spinner на селекторах |
| Empty | Empty: «Нет отпусков» + короткий текст + фокус на форму |
| Error (загрузка списка) | Alert danger + «Повторить» |
| Error (сохранение) | Ошибка у формы / toast; поля не сбрасывать |
| Conflict | Модал A3 до записи |
| Success | Toast/brief success; строка появляется в таблице |

## 6. Вкладка «Увольнение»

### 6.1. Структура

1. Alert тестового режима
2. Форма «Увольнение»
3. Превью влияния на константы (всегда после выбора пользователя)
4. Таблица записей увольнений (план / выполнено)

### 6.2. Поля

| Поле | Тип | Обязательно |
|------|-----|-------------|
| Пользователь | селектор Б24 | да |
| Когда | Radio: «Уволить сейчас» / «Уволить с даты» | да |
| Дата | DatePicker | да, если «с даты»; `≥ сегодня` |
| Замена в константах | селектор Б24 (опционально) | нет |

### 6.3. Превью констант

После выбора пользователя:

**Alert warning** (если есть совпадения):

> После деактивации сотрудника эти роли останутся привязанными к нему и фактически станут пустыми для БП, пока их не назначат вручную или через замену ниже.

Список названий констант (в тесте — «Проджект Б24» или empty).

Если замена **не** выбрана: вторичный текст — «Константы автоматически не изменятся.»  
Если замена **выбрана**: «При увольнении эти константы будут переведены на: [ФИО]. Автовозврата нет.»

### 6.4. Действия

| Действие | Результат |
|----------|-----------|
| Уволить / Запланировать увольнение | Модал B4 → при конфликте (есть замена) B3 → выполнение |
| Сбросить | Очистка |

### 6.5. Таблица

| Колонка | Содержание |
|---------|------------|
| Пользователь | Аватар + ФИО |
| Режим | Сейчас / С даты + дата |
| Замена | ФИО или «—» |
| Константы | Число / список кратко |
| Статус | Запланировано · Выполнено · Ошибка · Отменено |
| Действия | Отменить план (если запланировано) · Подробнее |

Автовозврата и кнопки «вернуть роли» нет.

### 6.6. Состояния

Аналогично отпуску: loading / empty / error / conflict / success.  
Empty превью: «У сотрудника нет ролей в глобальных user-константах» — тогда увольнение всё равно возможно, блок замены скрыт или disabled с пояснением.

## 7. Конфликт значения константы

**Когда:** при записи подмены/возврата/замены значение константы **уже не равно** ожидаемому (кто-то изменил вручную или параллельная запись).

**Модал (A3 / B3):**

- Заголовок: «Конфликт роли»
- Тело по каждой конфликтной константе:
  - Название константы
  - Ожидали: [ФИО]
  - Сейчас в портале: [ФИО или пусто]
- Действия **на каждую** константу (или общий выбор + список):
  - **Заменить** — записать целевое значение из сценария
  - **Оставить как есть** — пропустить эту константу
- Футер: «Применить выбор» (primary) · «Отмена» (отменяет всю операцию)

Не полагаться только на цвет кнопки: в тексте явно «будет записан заместитель / оригинал».

## 8. Тестовый режим

Пока включён флаг теста (логика Витька):

- **Banner** (info) на обеих вкладках:  
  > Тестовый режим: изменяется только константа «Проджект Б24». Остальные роли только показываются в списках и не записываются.
- В превью/таблицах роли вне теста помечать Badge «только просмотр» или приглушённым текстом.
- Конфликт и запись — только для «Проджект Б24».

## 9. Подтверждения

| Сценарий | Модал |
|----------|-------|
| Ручной возврат из отпуска | «Вернуть [ФИО] во все затронутые роли сейчас? Подмена заместителя будет снята.» Danger primary: «Вернуть» |
| Отмена запланированного отпуска | «Удалить запланированный отпуск? Подмена не начиналась.» |
| Уволить сейчас | Перечень констант + замена или предупреждение о пустых ролях. Danger: «Уволить» |
| Уволить с даты | То же + дата. Primary: «Запланировать» |
| Отмена плана увольнения | «Снять запланированное увольнение?» |

Уведомления портала (im/notify) **не** вызываем.

## 10. Адаптивность iframe

| Правило | Деталь |
|---------|--------|
| Ширина | Без горизонтального скролла; `min-width` контента ≤ контейнер |
| Отступы | Компактные токены Kit (`spacing`), не «лендинговые» |
| Форма | Одна колонка; на ≥720px даты «С»/«До» в один ряд (grid 2) |
| Селекторы | Полная ширина колонки; длинные ФИО — ellipsis + title |
| Таблица | Горизонтальный scroll **только внутри** table wrapper, не у всей страницы; на узком — приоритет колонок: Сотрудник, Период, Статус, Действия; Роли — в детали |
| Высота | `BX24.fitWindow` / resize после открытия модалок и смены таба (зона интеграции Витька) |
| Модалки | В пределах viewport iframe; длинный список конфликтов — scroll внутри body |
| Тач | Кнопки действий ≥ 32px по гайду Kit |

## 11. Доступность

- Фокус: видимое кольцо токенов Kit; в модалке focus trap
- Селекторы и даты доступны с клавиатуры
- Ошибки связаны с полями (`aria-describedby` / API FormField Kit)
- Статусы не только цветом: текст Badge
- Контраст — токены темы Б24


## 13. Что сознательно вне UI

- REST, cron, запись GlobalConst, деактивация пользователя — **Витёк**
- Права админа на увольнение на стороне портала — уточняет Витёк; UI всегда показывает подтверждение
- Календарь отсутствий Б24 и нотификации — не используем
