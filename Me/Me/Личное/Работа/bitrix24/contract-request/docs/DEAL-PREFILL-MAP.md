# Prefill формы из сделки (БП 608)

Портал: **ik-navigator** · placement `CRM_DEAL_DETAIL_TAB` · шаблон БП **608**

При открытии вкладки «Заявка на договор» поля формы заполняются из UF-полей сделки, если они не пустые.

## Код

| Файл | Назначение |
|------|------------|
| `api/html/deal-prefill-map.js` | Маппинг параметр БП ↔ UF сделки (источник правды для фронта) |
| `api/html/deal-prefill.js` | Загрузка `crm.deal.get`, расшифровка enum, `applyValues` |
| `export/deal-prefill-map.json` | Тот же маппинг в JSON (для отчётов и скриптов) |

## Порядок заполнения

1. **Prefill из сделки** — `BP608DealPrefill.load()`
2. **Черновик** — `localStorage` (если был — перекрывает prefill)

## Шапка сделки (не параметры БП)

Отдельно от формы, в `tab.html` → `loadDeal()`:

| UI | Источник | UF / метод |
|----|----------|------------|
| ФИО контакта | `crm.contact.get` | `CONTACT_ID` |
| Номер ГП (new) | сделка | `UF_CRM_1739347967` |
| Тип помещения + номер квартиры | сделка | `UF_CRM_1538729147` + `UF_CRM_1660535141` |
| Сумма (руб.) | сделка | `UF_CRM_1538728286642` |

| `Parameter3` — «ЗАПОЛНИ ФИО КЛИЕНТА» | Убран из UI; флаг БП, не UF сделки. ФИО — в шапке из контакта. |

## Особенности

- **Enum** — ID из сделки расшифровываются через `crm.deal.userfield.list`.
- **CRM-контакты** — один проход `buildDealContactStash` (ФИО + ID); `buildPayload` не дублирует `crm.contact.get`.
- **Порядок контактов (DnD)** — отложено; методика в [[CONTACT-ORDER-DND]].
- **Файлы** — в `<input type="file">` подставить нельзя; под полем подсказка «В сделке: …».
- **Отчёт по сделке** — в консоли браузера: `window.__bp608PrefillReport` (`filled`, `empty`, `files`).
